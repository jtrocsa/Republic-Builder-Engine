# Architecture Quick Reference

**Read this file first.** Consult the longer documents linked at the bottom only when you need deeper rationale than a bullet here provides. This file must be updated after every architecture or migration phase — see the update rule in `CLAUDE.md`.

## 1. Current project state

- The game is **Chronicle**, an AP U.S. History RPG. "Republic Builder Engine" is retired as the project's identity; the eventual multi-subject platform has no final name yet.
- **Chronicle covers CED Periods 1–5 of 9** as of Phase 67 — fifteen cases across five units, all with real, cited historical content. Unit 1 ("The Atlantic Crossroads," case-001–003), Unit 2 ("Colonial Crossroads," case-004–006 plus unit review), Unit 3 ("Common Cause," case-007–009), Unit 4 ("Democracy, Markets, and Reform," case-010–012) and Unit 5 ("A House Divided," case-013–015). Five walkable outdoor field maps and four interiors; twelve generated `.tmj` maps in the repository.
- The entire running game is one file, `apps/web/src/main.js` (13,065 lines as of Phase 71 — re-check with a quick line count before citing it if much time has passed, don't trust a stale figure) — no framework, no React/Vue/Phaser. Two plugin layers sit beside it and hold no APUSH facts: `apps/web/src/quest-types/` (six rubric-scored quest types) and `apps/web/src/engine/activities/` (four playable activity engines, Phase 68). Procedural Web Audio lives in `apps/web/src/engine/audio-engine.js`; real-accounts/classroom/submission/grading logic lives in `apps/web/src/repositories/` (`remote-*`/`progress-repository.js`/`teacher-override-repository.js`) and `apps/web/src/engine/` (`auth-flows.js`, `evaluator-requests.js`, `evaluator-client.js`, `custom-content-authoring.js`).

## 3. Current approved architecture

- Keep working code where it lives (`main.js`, `content/*.js`); wrap it thinly rather than moving it.
- Add `export` to specific pure functions worth unit-testing (collision math, badge logic, save-merge logic) and test them **in place** — no physical extraction of movement/collision/camera/NPC code.
- The long-term domain map (`PlatformCore`, `ContentRegistry`, `WorldComposition`, `QuestEngine`, `WorldRuntime`, `packs/<subject>/`) is real and documented, but is **future direction, not current structure** — see `PLATFORM-ARCHITECTURE-PROPOSAL.md`.

- Phase 61 — the cast's locomotion, scale and grounding: Phase 60 replaced the art but left the systems around it tuned for the placeholders. One ADR: `docs/decision-log/0044-cast-scale-locomotion-and-grounding.md`. **NPCs skated and the player glided.** NPCs ran on `setInterval` with a fixed per-tick displacement and no time scaling — 0.15–0.23 tiles/s against the player's 3.65, a twentieth — while `--sprite-cycle` was declared in the keyframe and set by nothing, so everyone animated at the 0.72s fallback: a 1.30-tile stride for the player, 0.05 for an NPC. `walkCycleSeconds()` now derives the cycle from ground speed via one `STRIDE_TILES` constant (player 0.30s reads as a run, NPC 0.81s as a walk), and NPC movement is time-based at 33ms with cached node lookups. **All 21 NPCs walked the same 0.9×0.65-tile rectangle** from three hand-written waypoint tables; a post is now a home anchor plus a radius and new `engine/npc-wander.js` picks reachable points inside it with varied pauses and idle turns, seeded per NPC id. Pre-existing and visible in the Phase 72 baselines. The fix is a content decision — number Units 2–5's case titles, or stop the eyebrow trying — not a patch. Found in Phase 74; see decision log `0057`.
- **`complicated` is offered in both audits and correct on no claim.** Phase 72 added the fourth classification by label and deliberately changed no authored answer, because promoting a claim to it un-settles that claim in every live save. Case 1.01's `fertile` is the obvious candidate — its `why` already reads "He is right. What he does not write is…" — and it is the owner's call. Units 3–5 should author `complicated` properly from the start. See `docs/design/CHRONICLE-VOCABULARY.md` §2.

- **Four sequencing quests across Units 3–4 ship pre-solved.** `renderSequencingQuest()` renders items in authored array order and never shuffles, so a quest whose `items` are written `position: 0,1,2,3,4,5` opens in the answer. Unit 1 authors its three scrambled and Unit 5's two are correct and assert it in e2e; Units 3 and 4 lost the convention. Unit 2's was the fifth and was fixed in Phase 70, because that pass already had the file open. Fixing the rest is a content edit to two shipped units. See decision log `0049` §6.
- **Unit 3 (Philadelphia, 1767) is still frozen on six `legacy-*` placeholder sheets.** No Revolutionary-era characters exist in the PixelLab account. Now blocked on generation spend rather than on work.
- **The Navigation Table's unit-tab list runs past the fold at 1366×768 with five units** and has four more periods to grow. It scrolls, so nothing is broken; how a nine-unit list should lay out is a design decision, not a bug fix.
- Still-registered art gaps: the Georgian/Federal columned statehouse, and the trades/forge group in `canonical-palette.js` — which is why Phase 64's blacksmith is posted beside a storage shed rather than an anvil. (`military.civilWar.camp` is **closed** as of the Phase 66 commission.)

## 6. Next approved phase

None scheduled. Per `POST-MINIMAL-ARCHITECTURE-REASSESSMENT.md` §7 and decision log `0033`, the standing product priority remains expanding real APUSH content into the CED's remaining periods — **Periods 6–9, now that 1–5 are shipped** — and not a new architecture phase. Nothing in Phases 65–70 changed the deferred-systems list in §8; the field-interior engine and the activity engines were both built inside the existing `main.js`/`FIELD_MAPS` structure precisely so they would not.

**TRACE now has content** (Riverbend's wharf ledger, Phase 70 — the owner moved it there from Canal Crossroads, which keeps its own for whenever Unit 4 is authored). What remains queued and unscheduled is **authoring activities for Units 3–5**: 18 of the 21 sources still route to the plain reader, and `docs/design/MISSION-ACTIVITY-CATALOG.md` §6 is the queue. When it is picked up, the optional content fields Phases 69–71 added (`howItWorks`, `terms`, `briefing`, and DISCREPANCY's `record.context`/`record.text`) are authoring defaults rather than extras — `tests/unit/activity-content.test.js` fails without the first two — and Phase 70's slate rule holds: no unit should repeat its neighbour's three engines, and an engine that does repeat should be pointed at a different question.

**Phase 71's authoring rules bind that work too**, and two of them are now failing tests rather than prose: `howItWorks` is **three steps and a note**, capped at four by the schema; and an INTERVIEW's answer grid is **deliberately sparse** — one useful answer, two short deflections, and at least one question per speaker left unauthored so their `fallback` fires. A full grid makes asking everyone everything strictly dominant, which is what both shipped interviews did until Phase 71. A `briefing` gives the mission a face on the Mission Instructions screen and is worth authoring wherever a person plainly hands the record over.

**Scope note for that work.** Each unit has exactly one field case (case-001, -004, -007, -010, -013) and two non-map ones. Only a field case can host an activity: the other ten declare no `sources` at all, and reaching one from `missionScreen()` needs a path that does not exist. So "activities for Units 3–5" means Philadelphia, Canal Crossroads and Richmond — three maps, 18 records. Phase 70 deliberately did not build the non-map path.

## 8. Deferred systems and tools

- **Tools deferred, not rejected:** Phaser 4.1.x, inkjs. Real candidates, no concrete forcing function yet for Phaser (no perf complaint exists yet). **inkjs's stated reason is now out of date** — it read "today's dialogue is one static line per NPC, no branching need exists yet," and `docs/design/MISSION-ACTIVITY-CATALOG.md` §3 is that need arriving on paper. **Still deferred, and Phase 68 strengthened the case rather than weakening it**: the INTERVIEW engine ships branching field dialogue — four questions put to seven speakers, answers that differ by pair — as a **flat content matrix plus a lookup**, in about 200 lines, with the NPC tables untouched. That is the whole feature inkjs was being considered for, delivered without a scripting language or its compiler. Revisit only if authored dialogue outgrows a lookup — see decision log `0050` and `0051`. **Playwright is no longer deferred** — see §7 above; Phase 29 shipped a real committed suite, not just ad hoc usage. **Tiled is no longer fully deferred**: `.tmj` rendering via `apps/web/src/engine/tiled-map-loader.js` is now an established narrow pattern for three real, live maps (Unit 2's Riverbend field since the Phase 7-era proof of concept, Unit 1's Caribbean field since Phase 12, and the Institute Archive Room since Phase 14 — see `docs/decision-log/0029-caribbean-tiled-rebuild.md` and `0030-archive-room-tiled-interior.md`). This is still not license for a bigger Tiled-authoring pipeline, a desktop-editor workflow, or a `QuestEngine` renderer registry. **As of Phase 53 collision is generated** rather than hand-coded — but from each generator's own stamps, written to `<map>.blocks.js`, not read back out of the `.tmj`; land/water masks stay hand-written predicates duplicated between `main.js` and the generators on purpose (decision log `0036`).
- **Architecture deferred, not rejected:** `WorldComposition` (Blueprints/AI-generation/Publishing, including the full `TeacherWorld`→`PublicationVersion` draft/publish/versioning pipeline — Phase 22's content overrides deliberately stayed a flat classroom-scoped patch, not this), `QuestEngine`'s renderer/evaluation registries, `WorldRuntime`, 2 of the proposal's 7 repositories still not built (`World`/`Asset` — `Auth`/`Classroom`/`Submission` are now real as of Phase 22, `Content`/`Progress` were already real), full `packs/<subject>/` extraction. Revisit only when a second real subject pack exists — not on a calendar schedule. **`PlatformCore` (Identity/Classroom/Enrollment) is no longer deferred** — a real (if minimal) version shipped in Phase 22 once a real teacher/classroom pilot became real, per the exact condition this section used to name.
- **Explicitly rejected:** Yarn Spinner (unshipped official JS runtime), H5P-as-platform-core (state-ownership conflict), Spine, LDtk, TexturePacker (no current problem they solve). Consider-later, not adopted: Storybook, Phaser Editor v5, Sentry, GitHub Actions CI, axe-core/Lighthouse CI.
